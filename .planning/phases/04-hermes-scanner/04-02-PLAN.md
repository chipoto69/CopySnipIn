<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| Scanner service -> PostgreSQL repositories | Evaluated wallet decisions become durable scanner state. |
| Provider payload summaries -> database | Source evidence can contain noisy or sensitive diagnostic values. |
| Scanner lifecycle -> operator wallet state | Automated scanner writes can affect pinned, blocked, active, and inactive status. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-04-02-01 | T | `WalletRepository` | mitigate | Add scanner-specific lifecycle methods that preserve pinned, blocked, and first-seen fields. |
| T-04-02-02 | R | `ScannerRepository` | mitigate | Persist scanner runs and per-wallet evidence transactionally with stable run keys and conflict constraints. |
| T-04-02-03 | I | `QualificationEvidence.raw_payload` | mitigate | Store compact redacted summaries instead of raw provider payloads. |
| T-04-02-04 | D | scanner persistence | mitigate | Treat database failure as failed/degraded cycle status rather than a process crash. |
</threat_model>
