<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| Process runtime -> Redis lock | Scanner process identity controls distributed overlap prevention. |
| OS signal -> scanner runtime | Shutdown requests can interrupt an in-progress cycle. |
| Runtime status -> heartbeat/logs | Scheduler failures and skipped overlap details become operator-facing diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-04-03-01 | D | scanner scheduler | mitigate | Run one cycle at a time, derive lock TTL from interval, and skip ticks when lock acquisition fails. |
| T-04-03-02 | E | Redis lock release | mitigate | Release only owner-token locks held by the current runtime instance. |
| T-04-03-03 | R | graceful shutdown | mitigate | Record shutdown status, complete in-progress cycles, and persist heartbeat details. |
| T-04-03-04 | I | startup errors | mitigate | Use existing settings redaction when scanner startup configuration fails. |
</threat_model>
