<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| settings -> database engine | Configured DSN crosses into SQLAlchemy engine creation. |
| repository input -> SQL statements | Future provider/domain data will cross into persistence helpers. |
| migration code -> live PostgreSQL | Alembic can change durable schema when explicitly run. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | T | Alembic baseline migration | mitigate | Use deterministic table/index/constraint names and metadata/migration coverage tests. |
| T-02-06 | R/T | DB session/repository primitives | mitigate | Require explicit transaction helpers and schema-level uniqueness for idempotency. |
| T-02-07 | I | DB URLs in migration/session errors | mitigate | Reuse Plan 01 redaction for settings errors; do not echo real `.env` values. |
| T-02-08 | D | Default test suite | mitigate | Keep live PostgreSQL migration checks opt-in/manual, not required by `uv run pytest`. |
</threat_model>
